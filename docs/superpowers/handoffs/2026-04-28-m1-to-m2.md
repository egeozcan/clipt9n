## Open considerations from M1's final review (M2 should know)

1. **Fixed-slot config (Important)** — `LanguagesConfig` uses concrete `slot_1/slot_2/slot_3` TOML keys. If M2's three slots ever go dynamic, the schema, struct, and `label_for_code()` all change together. Worth a short conversation before writing slot-binding code: stay with the fixed schema (simpler, matches spec) or switch to `Vec<LanguageSlot>` for future-proofing.
2. **`MockClipboard` is `#[cfg(test)]`-only** — unusable from `tests/` files. M2 might want to inject clipboard state without subprocess spawning. If so, expose behind a `test-utils` Cargo feature.
3. **`with_retry` panics on empty backoffs** — defensive early-return would be safer (currently unreachable, but worth fixing while in `client.rs`).
4. **`source_language` is threaded through `TemplateContext` but unused** — built-in templates don't reference it. Add a `// TODO(M4): inject whatlang result` comment in `prompts.rs` so the M4 engineer doesn't hunt for the hookup point.
