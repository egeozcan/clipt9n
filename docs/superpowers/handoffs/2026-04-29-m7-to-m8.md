## Open considerations from M7's review cycle (M8 should know)

1. **Per-task code-quality reviews caught real defects.** Eight fix-up commits across the milestone — every `feat(M7)` commit had a `fix(M7)` follow-up. If you're doing M8 with the same workflow, budget for it. The defects weren't "code style" — they were correctness gaps the implementer's self-review missed: orphaned events, false-positive heuristics, missing viewport restoration, panic paths, default animation flags. **Don't skip the per-task reviews to save time; they paid back 5× during M7.**

2. **The kittest harness is now indispensable.** M5 + M6 + M7 all had it; M8's test surface (M8.A unit + M8.B integration via wiremock) doesn't strictly need it for correctness, but `tests/kittest_a11y.rs` should grow during the VoiceOver pass to encode whatever the manual smoke surfaces. New regressions caught during M8's test pass should land as kittests.

3. **The hand-rolled construction match in `spawn_sample_translation_check`** stayed for M7 because the wizard wants `setup::default_base_url(provider_kind)` not `cfg.provider.base_url`. The two cleanest unifications: (a) add an `Option<&str>` base-URL override to `factory::build_provider`; (b) clone `cfg` and swap `base_url` at the call site. Both work. Pick one, or document the bypass as intentional and move on.

4. **`compute_tray_status` doesn't return `Warn(KeychainStaleKey)`.** Task 9's design settled on the ephemeral `tray.set_status` direct-call from `handle_translation_done`'s 401 arm. The next frame's `compute_tray_status` sees `SetupWizard` and returns `NoApiKey`, overwriting. The user effectively goes from `Ready` to `NoApiKey` — the amber `KeychainStaleKey` flip is a same-frame breadcrumb for the OS tray's event log, not a user-visible state. **Don't "fix" this in M8 by adding a `keychain_stale_key: bool` field** unless there's a concrete UX reason — the current design is intentional and documented.

5. **Tray-construction failure is non-fatal.** `main.rs` logs warn and runs without a tray. The hotkey path is always functional. **M8's CI should NOT assume a tray is present** — the macOS GitHub Actions runner may or may not provide a graphical session capable of NSStatusItem creation. Headless tray construction will Err; tests should not rely on a live tray.

6. **The 21-row manual smoke matrix** in `README.md` is the M8 polish-pass owner's checklist. **VoiceOver pass** is the most expensive single line on it (real screen-reader testing on prompt / history / wizard / tray-confirm modal). Allow ~half a day for it.

7. **Cross-platform discipline is provably enforced** by the M7 grep, but it's a manual ritual today. **M8's lint script (M8.J) makes it CI-fail-loud**, which is the long-term safety net. Land that before any other M8 cross-platform work — if it surfaces existing leakage, fix the existing leakage first.

8. **Test count cadence**: M1→M2→M3→M4→M5→M6→M7 ran roughly +20 to +30 tests per milestone. M8 should add ~80–120 (the unit-test backfill is the bulk: templates ~15, post-processing ~10, glossary scoping ~15, history crypto ~15, history store ~10, config round-trip ~10, plus integration suites). Target: ~360–390 tests at M8 close.

9. **Latency benchmark hardware**: spec §10 targets are p50<800ms, p95<2000ms with Haiku 4.5. **These are end-to-end, not provider-only** — they include clipboard read, Whatlang detect, template render, network round-trip, post-process, clipboard write. The benchmark must run on a real network from the dev box (not localhost wiremock); document the network conditions used.

10. **Fuzz target seeds**: `cargo-fuzz` needs corpus seeds. `glossary_parser_fuzz` should seed with a few real `glossary.toml` examples plus some adversarial cases (BOM, non-UTF-8, deeply-nested arrays, cycle-like references). `template_renderer_fuzz` should seed with the built-in templates plus adversarial Jinja constructs. `history_decrypt_fuzz` doesn't need a corpus — random bytes are the input.

11. **Packaging on macOS**: `cargo-bundle` is a thin config wrapper around `productbuild`/`pkgbuild`. The Info.plist needs `LSUIElement = true` (menu-bar-only), `CFBundleIdentifier` (unique reverse-DNS), `CFBundleVersion` and `CFBundleShortVersionString`, and the `clipt9n` binary as `CFBundleExecutable`. **Ad-hoc signing** (`codesign --sign -`) is fine for personal use; **notarization** requires an Apple Developer account and is out of scope for v1.0. Document the workaround (Right-click → Open → Open Anyway) in the README.

12. **The `[tray]` schema lives in `state.toml`, not `config.toml`.** Spec §6 has it under `[tray] visible = true` in *config*.toml, but M7's plan diverged (Task 2 cross-cutting decision) to put it in `state.toml` because the user shouldn't have to edit config.toml to recover from "Hide icon". M8's docs should reflect this — the README already does (mentions the per-OS state.toml paths) but check whether the spec PDF needs an addendum.

13. **No `TranslateError::Tray` variant**. The M6→M7 handoff suggested adding one; M7 used `TranslateError::Internal` instead. **Don't add `TranslateError::Tray` in M8** unless a real consumer needs to discriminate tray-class errors. The non-fatal-with-warn pattern is fine.

14. **GitHub Actions runner choice for macOS test matrix**: the macOS-13/14 runners can run `eframe` + global-hotkey under a software display server, BUT NSStatusItem requires a real NSApplication run loop. The kittest tests don't need a real display — they use AccessKit's headless mode. **For M8 CI: run the unit + kittest suites on every macOS PR; defer the live-tray smoke to a manual checklist** (it's already in the M7 README matrix).
