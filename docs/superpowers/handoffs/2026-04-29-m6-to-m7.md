## What's already there (M6 final state)

### Setup wizard + keychain modules

- `src/secrets.rs` (~290 lines) — `Secrets` trait now has three methods: `get_api_key() -> Result<Zeroizing<String>, _>`, `set_api_key(key: Zeroizing<String>) -> Result<(), _>`, `keychain_available() -> bool`. Two impls: `EnvSecrets` (env-var read, write returns `SetupWizard("env-secrets are read-only")`, keychain_available always false), `KeychainSecrets { service, account }` (read via `Entry::get_password()` mapping `Err(NoEntry)` to `MissingApiKey`, write via `Entry::set_password`, probe via `Entry::new(service, "_clipt9n_probe").get_password()` treating `Err(NoEntry)` as available). `pub fn resolve(&ApiKeyConfig) -> Box<dyn Secrets>` picks at startup based on `cfg.provider.api_key.source` ("keychain" → KeychainSecrets, anything else → EnvSecrets). `pub fn migrate_keyfile_to_keychain(path, service, account) -> Result<bool, _>` is idempotent (probes via `get_secret()`, returns `Ok(false)` if file missing or entry already populated), best-effort (failure logged at warn, M5 path still works).

## Open considerations from M6's final review (M7 should know)

1. **`ClipApp.secrets` is currently dead-but-allocated.** Per M6 big-bang review Fix 1: `persist_setup_completion` builds a fresh `KeychainSecrets` to avoid stale-account drift. The `self.secrets` field carries `#[allow(dead_code)]` waiting for M7. M7 revives it via the tray menu's "Re-run setup wizard" item — when the user clicks that, the App needs to construct a `SetupWizardModel` seeded from the *current* `cfg.provider.kind` + `secrets.keychain_available()`, transition to `AppState::SetupWizard`, and resize the viewport. The `secrets` field is the natural place to read `keychain_available()` without re-resolving from `cfg`.

2. **Provider construction in `main.rs` uses a placeholder key on first launch.** Per M6 Task 10: when `secrets.get_api_key()` returns `MissingApiKey`, main.rs falls back to `Zeroizing::new("placeholder-no-key".into())` so the AnthropicProvider/OpenAiCompatibleProvider construction succeeds. The wizard's checks build their own provider from the user's typed key. After Save-and-start, the running `self.provider` STILL has the placeholder; the user must restart for the new key to take effect on the next translation. **M7 should consider** whether to add a "live provider rebuild on Save-and-start" path. Mitigation today: the wizard's Verify proves the key works before Save-and-start unlocks; the only cost is a one-time restart. If M7 doesn't tackle this, document it more visibly in the wizard's "Save and start" success toast.

3. **The "Get your API key" label is currently informational text.** Per M6 Fix 5: removed the design's clickable arrow because the M6 plan didn't include the per-provider URL table. M7 has `Platform::open_path` already; just add a `provider_key_url(provider_kind) -> &'static str` helper to `ui/setup.rs` (Anthropic console URL, OpenAI console URL, Google AI Studio URL, Ollama install docs URL) and wire `ui.link(...).clicked()` to call `platform::open_path`. ~10 lines of code.

4. **`Zeroizing<String>` discipline at every secret boundary.** Established in M1, M5, M6. M7's tray menu doesn't introduce new secret boundaries directly, but the "Re-run setup wizard" path will resurface the key in the wizard model. Don't accidentally let a `String` leak through `format!()` calls in any new tray code (the tray menu shouldn't render the key at all — only the status pill).

5. **Tray icon vs. dock icon (macOS).** `eframe` puts the app in the dock by default. The design implies a menu-bar-only app (no dock icon). M7 needs to set the macOS bundle's `LSUIElement` plist key to `true` to hide from dock. This is a packaging concern, not a runtime one — it lands when M8 adds `cargo-bundle` config, but M7 should write up the requirement in its plan so M8 doesn't miss it.

6. **`tray-icon` crate dep version.** Pin to whatever's egui-0.31-compatible. As of writing, `tray-icon = "0.20"` is current; verify before pinning. Don't bump beyond what's compatible with the eframe/egui pins.

7. **Hide-confirm modal lives in `src/ui/`.** The design's `TrayMenu` confirm-hide is a modal showing the live hotkey from `cfg.hotkey_display()` (which already exists since M2). New file `src/ui/tray_modal.rs`; new `AppState::ConfirmingTrayHide { hotkey_display: String }` variant. Mirror M5's `ConfirmingClearAll` shape. Add 1-2 kittest tests.

8. **State.toml grows a `tray_visible` field.** When the user picks "Hide icon → Confirm", write `tray.visible = false` to state.toml. On launch, if the value is false AND `--show-tray` CLI flag is NOT present, skip tray construction. The CLI flag is the documented recovery path.

9. **Reload-glossary already has a channel.** The M4 SIGHUP handler sends `()` into `glossary_reload_tx`. The tray menu's "Reload glossary" item just clones that sender and sends. Don't introduce a new reload mechanism.

10. **No M4 / M5 follow-ups in M7.** Per M5 plan §11.X (deferred to M8): Jinja conditional-branch validation, glossary entry-validation, source-text lowercasing hoist, double-detection elimination, `[glossary] matching` value validation, plus the latency benchmarks and `cargo-fuzz` targets. M7's plan should add a third manual matrix covering tray-icon-on-Linux/macOS/Windows, hide-and-recover via `--show-tray`, glossary-launch on each OS, accessibility-permission-revoked surfacing, and keychain-stale-key surfacing.
