## What's already there (M3 final state)

### Five-state app + cancellation
- `src/app.rs` — `ClipApp` eframe app with `AppState::{Idle, Showing, EnteringCustom { model }, ConfirmingSize {…}, Translating { gen, action_label, overlay_label, started_at }}`. The `match std::mem::replace(&mut self.app_state, AppState::Idle)` pattern in `update()` dispatches by-value to per-state handlers (`update_showing`, `update_entering_custom`, `update_confirming_size`, `update_translating`). Each handler restores or transitions the state.
- `dispatch_gen: u64` cancellation counter. `start_translation` bumps it; `handle_translation_done` drops outcomes whose `gen` ≠ current. The user pressing Esc or clicking Cancel during translation bumps `dispatch_gen` and dismisses to Idle — the in-flight HTTP request continues to its 30s natural timeout but its outcome is dropped silently.
- Worker + watcher spawn pattern. `start_translation` spawns the translator and a watcher; if the worker panics, the watcher converts the `JoinHandle` error into `TranslationOutcome { result: Err(TranslateError::Internal) }`, guaranteeing `tx.send` always fires. The "Translation failed: internal error" toast appears and the app returns to Idle. **Don't undo this defense in M4** — it caught a real Turkish-input UTF-8 boundary panic during M3 manual testing.
- `Intent` enum + `decide_intent(slot, _source_text, cfg)` is the pure slot-to-action mapper, unit-tested for all 6 slots (and slot 0/7 returning `None`). `requires_size_confirm`, `next_gen`, `overlay_label_for`, `action_label_for` are all `pub(crate)` testable helpers in `app.rs`.

### Focus discipline established in M3
The full ruleset, mostly in code comments:
1. **Initial focus is set by the caller (`app.rs`), not the renderer.** App tracks `initial_focus_pending: bool` (set in `show_window`, consumed in `update_showing`). The renderer takes a `focus_target: Option<u8>` parameter and `request_focus`'s the matching widget.
2. **Click takes priority over global keys.** `outcome = click.or(key)` (NOT `key.or(click)`). This was twice-broken during M3: once in size-confirm (focused Cancel + Enter would emit Confirm), once in the prompt's Enter→RepeatLast handler. Both fixed; the broken pattern is now in the muscle memory of the codebase comments.
3. **Focus rings on accent backgrounds use `ACCENT_INK` (very dark)**, not `ACCENT`. ACCENT-on-ACCENT is invisible. `src/ui/custom_prompt.rs::run_button` and `src/ui/size_confirm.rs::confirm_button` follow this pattern.
4. **Custom widget chips/buttons MUST emit `widget_info`.** Audit: every `Sense::click()` allocation has a corresponding `widget_info` call (often inside the helper, not at the call site). The reduced-motion static label also has `widget_info` so screen readers announce "Translation in progress" (WCAG 4.1.3).
5. **Footer kbd kerning.** `theme::window_frame`'s body sets `item_spacing.x = 0` (so vertically stacked Frames hug). Each footer's `ui.horizontal` scope must override with `item_spacing.x = 4.0` so kbd caps don't visually touch their adjacent labels. M4's glossary chip strip should set `item_spacing.x = 6.0` if rendered horizontally (matches custom-prompt's preset-chip row).

## Open considerations from M3's final review (M4 should know)

1. **Layout is tight at 470px window height.** All 6 slots + header + preview + footer just barely fit. M4's glossary chip strip needs to either be capped at a small fixed height (e.g., one row of chips, ~28px including gap) or the strip needs to live ABOVE the slot list (not below) so it's the slot list that gets clipped on overflow rather than the glossary preview. Recommendation: chip strip is one wrap-row, max ~28px, between preview block and slot list. Use `Label::truncate()` on chip text if any chip's term is unusually long.

2. **`reduced_motion` is read once at startup.** Cached on `App.reduced_motion`. M4 inherits this. Don't re-query per frame.

3. **The `_secrets` parameter on `ClipApp::new` is currently dead.** It accepts `Box<dyn Secrets>` and drops it. M6 will revive it for keychain support. M4 doesn't need to touch it.

4. **The TODO at `src/ui/translating.rs:101-103`** — the overlay subtitle currently shows a literal "request → api endpoint" placeholder. Spec calls for the actual provider host (e.g., `api.anthropic.com` from `cfg.provider.base_url`). Wire it in M4 if convenient (read the host from the URL); otherwise carry forward to M8 polish.

5. **`_source_text` parameter on `decide_intent`.** Currently unused (underscore-prefixed). M4 might use it: spec §13 says the source-language detection happens in glossary loading, and `decide_intent` could consult it for "did the user pick the same target language as the source?" warnings. If M4 doesn't use it, drop the param and update the helper signature.

6. **Worker panic recovery via `TranslateError::Internal`.** Established in M3. M4's glossary loading code should NOT panic on malformed input; spec says "malformed glossary disables glossary for the session, logs warn at startup, app continues." If glossary loading panics anyway, the `Internal` error variant is the right surface for it. Prefer `Result<_, TranslateError>` returns in glossary code throughout.

7. **Cross-platform discipline.** M4's SIGHUP handler is the first new `cfg(unix)` block since M2. Place it in `src/platform/unix.rs` (new file), expose via the `Platform` trait with a `register_sighup_handler(&self, callback: Arc<dyn Fn() + Send + Sync>) -> Result<(), TranslateError>` method (or similar). Default impl: `Ok(())` (no-op for Windows). Linux/macOS impl: register a real `signal_hook` or `nix::sys::signal` handler. **Don't** put the cfg block in app.rs or anywhere else.

8. **Manual smoke discovered three classes of M3 bugs that all-tests-passing missed.** They were: (a) Turkish source-text panic in post-processing, (b) stuck overlay when worker panicked, (c) preview line wrap blowing up the layout, (d) focus rings missing/invisible on accent-bg buttons and chips. Tests caught nothing. **M4 must include manual VoiceOver-like smoke as part of plan exit criteria** — at minimum, build the release binary, exercise glossary lookup with non-ASCII source text, and verify reload-via-SIGHUP works. Don't trust green tests alone.

9. **M4's plan structure should mirror M3's.** ~11 tasks, each TDD-style with bite-sized steps and exact code. Self-review section. Cross-cutting glossary at the top. Reference the M3 plan path verbatim.
