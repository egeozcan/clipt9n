## What's already there (M4 final state)

### Glossary module
- `src/glossary.rs` (~840 lines) — `GlossaryEntry { source, target, languages, note }`, `Glossary::{load, empty, entries, len, is_empty, entries_mut, matching_entries, preview_entries}`. Loader is graceful (missing file → empty Ok; malformed → `TranslateError::Glossary` Err that the caller logs warn and substitutes empty). `MatchingStrategy::{Auto, WordBoundary, Substring}` with `parse(&str)` and `default_strategy(iso3)`. `detect_source_lang(&str) -> Option<String>` via whatlang with `LANG_CONFIDENCE_THRESHOLD = 0.5`. `iso3_to_iso2`/`iso2_to_iso3` mapping tables for pair-key formation. `format_block(&[&GlossaryEntry])` produces the spec §5.4 verbatim format. `term_matches` is regex-free — manual word-boundary scan. **The `entries_mut` method is gated `#[cfg(any(test, feature = "internal-test-helpers"))]`** — M5 history tests can use the same `internal-test-helpers` feature pattern if they need fixture-loaded data.

### Templates module
- `src/llm/templates.rs` — `Templates { translate, fix_grammar, rewrite, custom }` (owned `String`s). `Templates::built_in()` (no-fs, used in tests + as default fallback). `Templates::load(config_dir, &TemplatesConfig)` is strict — calls `validate_template_source` per kind, parses + renders with stub vars, errors carry `<file> line <N>: parse error: …` or `<file> line <N>: undefined variable or render error: …`. `render(&Templates, kind, &TemplateContext)` uses `UndefinedBehavior::Strict`. **Caveat (documented as M4 limitation):** Jinja conditional branches that don't fire under stub values escape startup validation — a template with `{% if glossary_block %}{{ undeclared_var }}{% endif %}` validates clean and crashes at first real translation. Doc'd in README; not a blocker.

### Translator integration
- `src/translator.rs` — `Translator::new(cfg, provider, &Templates, &Glossary)` is the new 4-arg shape. `execute` runs `detect_source_lang → iso3_to_iso2`, takes `target_iso2` from `Action::Translate { code }` (None for FixGrammar/Rewrite/Custom), calls `glossary.matching_entries(...)`, formats via `format_block`, threads block into the appropriate `TemplateContext::for_*` constructor.
- `decide_intent`'s dead `_source_text` parameter was dropped in M4. Don't accidentally re-add it.

### App ownership
- `src/app.rs::ClipApp` holds `templates: Arc<Templates>`, `glossary: Arc<RwLock<Glossary>>`, `glossary_path: PathBuf`, `glossary_reload_rx: CrossbeamReceiver<()>`. Constructor is 10 args + `#[allow(clippy::too_many_arguments)]`.
- `start_translation` worker clones the Arcs, takes a `read().clone()` snapshot of the glossary at dispatch time, and constructs `Translator::new(&cfg, provider.as_ref(), &templates, &g_snapshot)`. **Don't break this snapshot pattern** — it's what lets SIGHUP-driven reloads not perturb in-flight workers. M5 history insert should follow the same shape: clone the connection handle into the worker, never share a `MutexGuard` across `await`.
- `App::reload_glossary` is `pub(crate)` and runs sync I/O on the egui update thread. It's commented as acceptable for small files; the SIGHUP frequency is user-driven, not periodic. M5 history queries can have similar discipline if M7 adds a tray "Refresh history" menu item.
- `App::install_glossary_reload(tx)` is `pub` and infallible (`-> ()`). Signal install via `platform::install_sighup_reload` happens **synchronously** inside an `rt.enter()` guard — not inside the spawned task. This was a real bug in initial M4 (`pkill -HUP` killed the process); the fix is in `src/platform/unix.rs::install` and the rationale is a multi-paragraph comment there. **M5: if you add another signal listener (e.g., `SIGUSR1` for "force-flush history"), follow the same synchronous-install pattern.**

## Open considerations from M4's final review (M5 should know)

1. **`Arc<RwLock<_>>` worked well for the glossary swap, but history wants a different shape.** History reads happen on `Cmd+Shift+H` (rare, user-driven); writes happen on every translation success (high-frequency). Use `Arc<Mutex<rusqlite::Connection>>` and clone the Arc into workers; `rusqlite` is `Send` but not `Sync`, so the Mutex is mandatory. Take the lock briefly (insert query is sub-millisecond on a local SQLite); never hold across `await`.

2. **Sync I/O on the egui update thread is OK for small files, NOT for arbitrary queries.** M4 reload reads ~10KB synchronously; that's fine. M5 history queries, especially with search filter on 100+ entries with full-text decryption per row, may exceed one frame. Spec §11 sets a `<50ms p95` target with 100 entries — measure on real hardware. If it breaches, run the query on the tokio runtime and post results to the UI via the existing `result_rx` pattern (you can add a parallel `history_rx`).

3. **Defer M4 follow-ups to M8.** The M4 final review left these open: (a) document the Jinja conditional-branch unknown-variable validation gap, (b) validate empty `source`/`target` glossary entries at load time, (c) hoist source-text lowercasing in `term_matches`, (d) thread `detected_lang` from prompt model into translator to avoid double-detection, (e) validate `[glossary] matching` config value at load (warn on typos). All flagged as "follow-up, not blocker." Don't sneak them into M5 — keep the milestone focused.

4. **The `entries_mut` + `internal-test-helpers` feature pattern is the right shape for test fixtures.** M5's `History` will need a similar in-memory or on-disk-tempfile constructor for tests. `History::in_memory(&key) -> Self` (using `rusqlite::Connection::open_in_memory()`) is cleaner than feature-gating.

5. **Worker panic recovery (M3) is preserved through M4 and must continue.** `start_translation`'s watcher-spawn pattern catches panics in the translator and converts them to `TranslateError::Internal` → toast → Idle. M5 history insert is best-effort and runs AFTER the clipboard write succeeds, so a panic there shouldn't propagate — but wrap the insert in a separate watcher OR `tracing::warn!` the panic and continue. Don't let history corruption take down the translation flow.

6. **Reduced motion (M3) is cached on `App.reduced_motion`, queried once at startup.** M5's history viewer doesn't have animations per the design, but if you add scroll-to-selection, respect the same flag.

7. **Cross-platform discipline.** M5's keyfile path uses `directories::ProjectDirs` (already a dep). Permissions setting (`0o600` on Unix) requires `cfg(unix)` — put it in `src/platform/unix.rs` (the file exists; add a free function `set_owner_only_permissions(path: &Path)`). On Windows the keyfile is owner-readable by default via `wincred` ACLs, but in M5 we're using a plain file fallback; document that "keyfile mode" is less secure than M6's keychain mode and that Windows users get the same warning that Linux-without-Secret-Service users will get in M6.

8. **The `tracing::warn!` + fallback-to-empty pattern from M4 generalizes.** Spec §8: "History DB corruption → toast 'History database unreadable. New history will not be saved.' App continues to function; user can delete `history.db` manually to reset." Mirror M4's glossary path: try to open at startup, on `Err` log warn + show one-shot toast on first hotkey + set a `history_disabled: bool` field on App to short-circuit subsequent inserts.

9. **Plan structure.** Mirror M4's plan: ~11 tasks, each TDD-style with bite-sized steps and exact code. Self-review checklist at the end with spec-coverage table. Cross-cutting decisions glossary at the top. Reference the M4 plan path verbatim.

10. **Manual smoke caught two real bugs in M4 that all-tests-passing missed.** They were: (a) egui `Label` selectable-text default eating clicks on slot rows (looked fine in tests because tests don't simulate mouse position over text widgets), (b) `tokio::signal::unix::signal` registered inside the spawned future raced with `pkill -HUP` and let the kernel kill the process. **M5 must include manual VoiceOver-like smoke as part of plan exit criteria** — at minimum: build the release binary, exercise translate-then-restart-then-history-viewer, verify Cmd+Shift+H opens the viewer with the previous entry, exercise search/delete/clear-all, simulate corruption by deleting `.history-key` and confirm graceful degradation. Don't trust green tests alone.
